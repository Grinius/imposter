# Imposter web SEO

Read `docs/SEO.md` and inspect the current routes/content. Keyword metrics are pending unless a later dataset or decision documents them.

When researching, record source, date, market, and search intent. Separate the party game from other meanings of imposter. Cluster synonyms into useful destinations, and distinguish measured volume/difficulty from estimates. Do not infer easy ranking from a keyword score alone.

When building pages, provide a functional tool, concrete rules, or curated examples that satisfy the intent. Link category content into playable presets. Avoid one near-identical page per keyword. Do not let examples reveal an active game's secret. Keep user-facing copy natural and truthful, without fabricated popularity or review claims.

Verify public content exists in rendered HTML, links are crawlable, metadata/canonicals match actual routes, and sitemap/indexing directives exclude private rooms and unwanted filter variants. Robots directives are not authentication. Choose structured data only after checking current official eligibility and visible content.

Measure loading and interaction costs with the game assets present. Keep essential controls usable while decorative assets load. Explain lab versus field evidence and never promise rankings. Update the keyword map/SEO document when real data changes the strategy.
